1. Gambaran Umum

Project ini adalah aplikasi website OSIS sekaligus sistem e-voting. Hosting tidak hanya berarti “mengunggah file”. Aplikasi membutuhkan tiga tempat berbeda:

  • Vercel menjalankan aplikasi web.
  • TiDB Cloud menyimpan data siswa, admin, kandidat, periode pemilihan, suara, sesi, dan konten.
  • Vercel Blob menyimpan foto yang diunggah dari panel admin.
Analogi sederhana: Vercel adalah gedung tempat aplikasi melayani pengunjung. TiDB adalah lemari arsip data. Vercel Blob adalah gudang foto. Ketiganya harus terhubung agar aplikasi bekerja lengkap.
Penting soal branch: konfigurasi Vercel berada di branch fix/admin-gallery-previews. Saat pemeriksaan dibuat, main belum memuat file vercel.json, Dockerfile, dan konfigurasi deployment terbaru. Deploy branch aktif ini, atau merge perubahan tersebut ke main terlebih dahulu.

2. Arsitektur Hosting

Browser
   |
   v
Vercel
   |
   +-- vercel.json: semua request diarahkan ke service app
           |
           +-- Dockerfile
                 +-- FrankenPHP + PHP 8.4
                 +-- Caddy web server
                 +-- Laravel public/index.php
           |
           +-- TiDB Cloud (MySQL-compatible, port 4000, SSL)
           |
           +-- Vercel Blob (foto publik)

Alur request:

  1. Pengunjung membuka URL Vercel.
  2. Vercel membaca vercel.json.
  3. Semua URL diteruskan ke container bernama app.
  4. Container menjalankan FrankenPHP.
  5. Caddy melayani folder /app/public.
  6. Path yang tidak berupa file diteruskan ke Laravel melalui index.php.
  7. Laravel membaca database dan, bila perlu, URL foto dari Blob.

4. Persiapan Sebelum Deploy

4.1 Akun dan akses

  • Akun GitHub dengan akses repository.
  • Akun Vercel.
  • Pilih region TiDB sedekat mungkin dengan Function Vercel. Untuk pengguna Indonesia, pertimbangkan TiDB Singapore dan Function Vercel sin1; konfigurasi region belum ada di repo, jadi lakukan setelah verifikasi deployment.
  • Akun TiDB Cloud.
  • Akses domain, jika memakai domain sendiri.

4.2 Periksa branch dan file

git status
git branch --show-current
git log --oneline -8
ls vercel.json Dockerfile Caddyfile VERCEL_ENV_CHECKLIST.md

Pastikan working tree bersih. Jangan commit .env, password database, token Blob, atau private key.

4.3 Uji lokal

composer install
cp .env.example .env
php artisan key:generate
php artisan migrate
php artisan serve

Buka http://127.0.0.1:8000. Uji login, admin, voting, upload foto, export PDF, dan export Excel.

Jangan memakai data contoh dari seeder untuk pemilihan nyata tanpa meninjau ulang. AdminSeeder membuat username admin dengan password awal admin123; segera ganti password setelah login.

5. Menyiapkan Database TiDB Cloud

  1. Buka TiDB Cloud → My TiDB → Create Resource → Starter. Pilih nama, cloud provider, dan region. Untuk AWS, Singapore tersedia. Setelah jadi, buka Connect → Public → Generate Password; password hanya tampil sekali. Username TiDB wajib memakai prefix instance, misalnya xxxx.root.
  2. Pakai database bawaan test, atau buat database lain lewat SQL Editor TiDB.
  3. Buat user dan password database.
  4. Catat host, nama database, username, password, dan sertifikat CA.
  5. Gunakan koneksi MySQL-compatible. Checklist project menggunakan port 4000.
  6. Jangan memasukkan kredensial ke GitHub.

Database menyimpan tabel utama berikut: siswa, admin, periode pemilihan, kandidat, votes, konten OSIS, galeri, sessions, cache, jobs, dan migrations. Database juga memiliki constraint unik agar satu siswa tidak dapat memilih dua kali pada periode yang sama.

Menjalankan migrasi

Preview dahulu perubahan schema:

php artisan migrate --pretend --force

Jika SQL sesuai dan koneksi berhasil, jalankan:

php artisan migrate --force
TiDB dapat memiliki perbedaan dukungan terhadap fitur atau index MySQL tertentu. Jika migrasi gagal, baca error pertama, sesuaikan migrasi yang bermasalah, lalu ulangi. Jangan menghapus data produksi sembarangan.

6. Menyiapkan Vercel Blob

  1. Buka project Vercel.
  2. Buka menu Storage.
  3. Buat store Blob.
  4. Pilih akses Public, karena foto ditampilkan di halaman publik.
  5. Hubungkan Blob store ke project.
  6. Saat membuat store, centang Add a read-write token env var to this connection agar BLOB_READ_WRITE_TOKEN dibuat. Library PHP project ini membaca token tersebut; token wajib ada.
  7. Redeploy setelah Blob terhubung.

Class App\Services\BlobStorage memvalidasi JPEG, PNG, GIF, dan WebP maksimal 4 MB, lalu mengunggah foto sebagai URL Blob publik. File lama yang berupa basename masih dicari di public/image; path lama tertentu masih dapat memakai konfigurasi R2 sampai migrasi selesai.

7. Menyiapkan Project Vercel

  1. Push branch yang berisi konfigurasi deployment ke GitHub.
  2. Di Vercel pilih Add New → Project.
  3. Import repository GitHub.
  4. Pilih branch deployment yang benar.
  5. Gunakan framework Other, karena project memakai container custom.
  6. Biarkan Vercel membaca vercel.json.
  7. Isi Environment Variables sebelum deploy pertama atau sebelum redeploy.

vercel.json menunjuk ke Dockerfile. Jangan mengganti konfigurasi ini menjadi preset Laravel biasa tanpa menguji ulang routing dan runtime.

9. Deploy Langkah demi Langkah

Urutan ringkas

  1. Siapkan TiDB.
  2. Siapkan Blob Public.
  3. Isi Environment Variables.
  4. Import repository dan pilih branch yang benar.
  5. Deploy.
  6. Buka Logs dan pastikan container start tanpa error.
  7. Jalankan migrasi terhadap TiDB.
  8. Seed data awal hanya jika diperlukan.
  9. Uji semua alur.

Jika memakai Vercel CLI

npm install -g vercel
vercel login
vercel link
vercel env pull .env.local
vercel deploy --prod

Perintah vercel env pull menghasilkan .env.local. Laravel tidak otomatis membaca file itu sebagai .env; jangan commit file tersebut. Untuk local testing, salin variabel secara aman ke environment lokal sesuai kebutuhan.

Build yang dilakukan Dockerfile

  1. Memakai FrankenPHP PHP 8.4.
  2. Memasang ekstensi pdo_mysql, gd, zip, dan opcache.
  3. Mengatur upload maksimal 4 MB per file dan post body 5 MB.
  4. Menjalankan Composer production install tanpa dependency dev.
  5. Membuat folder cache, session, view, log, dan bootstrap cache.
  6. Menjalankan FrankenPHP sebagai user www-data.

10. Migrasi dan Data Awal

Setelah deployment pertama berhasil, jalankan migrasi menggunakan koneksi production. Pilihan paling aman adalah menjalankan Artisan dari lingkungan yang memiliki kode project dan environment production, bukan mengandalkan filesystem container yang sementara.

php artisan migrate --force

Untuk data awal:

php artisan db:seed --class=AdminSeeder --force
php artisan db:seed --class=SiswaSeeder --force
Seeder berisi data contoh siswa dan password awal admin. Untuk production nyata, review isi seeder dahulu. Hindari menambahkan data demo ke sistem pemilihan yang sudah berisi data sekolah.

12. Keamanan, Batasan, dan Operasional

  • Jangan simpan upload penting di disk lokal container. Filesystem Vercel bersifat sementara; aplikasi sudah mengarahkan foto ke Blob.
  • Request sekitar 4,5 MB. Galeri mendukung beberapa file, tetapi unggah batch kecil agar total body tidak melewati batas.
  • Blob memiliki kuota/operasi. Checklist project mencatat Vercel Blob Hobby 2.000 advanced operations per bulan. Hapus foto lama dengan hati-hati.
  • Queue dan scheduler. Vercel tidak menjalankan worker atau scheduler permanen; konfigurasi queue memakai sync.
  • Session harus database. Tabel sessions wajib sudah termigrasi.
  • APP_DEBUG harus false. Error detail dapat membocorkan konfigurasi dan query.
  • HTTPS dan proxy. Bootstrap mempercayai proxy Vercel agar URL dan request HTTPS diproses benar.
  • Password. Ganti password admin default. Gunakan password unik dan jangan membagikannya di chat publik.
  • Backup. Atur backup/restore TiDB sebelum pemilihan. Blob juga perlu rencana pemulihan file.
  • Hobby. Function maksimal 300 detik, request body sekitar 4,5 MB, satu region. Blob Hobby mencakup 1 GB storage, 10.000 simple operations, 2.000 advanced operations, 10 GB transfer per bulan. Setelah limit Blob terlampaui, akses dapat berhenti sampai periode berikutnya. Periksa Terms Vercel sebelum pemakaian resmi.

14. Operasional, region, log, dan rollback

Container Vercel dapat scale-to-zero setelah idle. Request pertama sesudahnya mungkin lebih lambat. Buka tab Logs untuk melihat stdout/stderr. Container tidak mempunyai IP keluar tetap; karena itu firewall TiDB tidak dapat dibatasi ke satu IP Vercel. Gunakan TLS dan password database kuat.

Untuk latensi, letakkan Function dekat database. Repo belum menetapkan region. Jika TiDB di Singapore, tambahkan "regions": ["sin1"] hanya setelah deployment diuji; perubahan konfigurasi region adalah perubahan deployment.

Rollback: Vercel Dashboard → Deployments → menu titik tiga pada deployment sebelumnya → Instant Rollback. Hobby hanya dapat rollback ke production deployment sebelumnya. Rollback tidak membatalkan migration atau perubahan environment variable; cek database terpisah.

15. Legacy R2 dan Pembersihan

Project masih membawa dependency Flysystem S3 dan dukungan URL lama agar file lama dapat ditampilkan. Jangan menghapus R2 terlalu cepat.

  1. Pastikan semua foto lama terbuka.
  2. Pastikan database sudah berisi URL Blob untuk foto baru/migrasi.
  3. Backup daftar file lama.
  4. Baru hapus environment variable AWS_*, dependency league/flysystem-aws-s3-v3, dan bucket R2.
